PostgreSQL considerations                                   

Connections to a PostgreSQL server can either use the QPSQL PostgeSQL driver or an ODBC driver such as psqlODBC. Unlike MySql or SqlServer, PostgreSQL does not allow a connection to be changed to a different database. To connect to a different database, the current connection must be closed and a new connection be opened. As a result, when using ODBC and supplying a DSN, the DSN must specify the database and as a practical consideration, there must be a DSN defined for each specific database that will be connected. However, ODBC also allows the use of a connection string which specifies the particular database. Therefore only one DSN ever needs to be defined for ODBC connections to PostgreSQL, and that is to establish driver, e.g. {PostgreSQL Unicode(x64)} to be used. The connection string supplies the other parameters for a connection such as: Host, port, user ID, password and database.

Installing a SSL certificate on Windows

Installing an SSL certificate for PostgreSQL involves configuring both the server and potentially the client to use encrypted connections.

Server-Side Configuration:

  • Generate or Obtain SSL Certificates:
    • Self-Signed: For testing or internal use, you can generate a self-signed certificate and a private key using tools like OpenSSL. Trusted CA: For production environments, obtain a certificate signed by a trusted Certificate Authority (CA).
  • Place Certificate Files:
    • Copy the server certificate (server.crt), private key (server.key), and optionally the CA certificate (root.crt) to a secure location accessible by the PostgreSQL user, typically within the PostgreSQL data directory. Ensure the private key file has strict permissions (e.g., chmod 0400) and is owned by the PostgreSQL user.
  • Configure postgresql.conf:
    • Open the postgresql.conf file (located in the data directory). Set ssl = on. Specify the paths to your certificate, key, and CA files:

Code

  • ssl_cert_file = 'path/to/server.crt'
  • ssl_key_file = 'path/to/server.key'
  • ssl_ca_file = 'path/to/root.crt' # Optional, if using client certificate verification
Configure pg_hba.conf: Open the pg_hba.conf file (located in the data directory). Modify or add entries to enforce SSL for specific connections. For example, to require SSL for all connections from any IP: Code
  • hostssl all all 0.0.0.0/0 md5
If requiring client certificate verification, add clientcert=verify-ca: Code
  • hostssl all all 0.0.0.0/0 md5 clientcert=verify-ca
Restart PostgreSQL: Restart the PostgreSQL service to apply the changes. Client-Side Configuration (if requiring client certificates or for secure connections): Obtain Client Certificates: . If clientcert=verify-ca is enabled on the server, the client needs a certificate and key signed by the same CA as the server. Configure Client Application: . Depending on the client, you may need to specify the SSL mode (e.g., require, verify-ca), and provide paths to the client certificate, key, and CA certificate. For example, in psql: Code
  • psql "sslmode=require sslcert=client.crt sslkey=client.key sslrootcert=root.crt host=your_host user=your_user dbname=your_db"
Verification: After restarting, connect to the database and execute SHOW ssl; to confirm SSL is enabled. Test client connections to ensure they are using SSL as intended.

To create a self-signed certificate for localhost on Windows, you can use the mkcert tool, which simplifies the process significantly. Prerequisites: Chocolatey: If you don't have it, install Chocolatey, a package manager for Windows, by following the instructions on its official website.
Steps:

  1. Install mkcert: Open an elevated PowerShell or Command Prompt and run the following command:
    2. Code:< choco install mkcert
  2. Install the local CA: Once mkcert is installed, run this command to create and install a local Certificate Authority (CA) in your trust store:
    3. Code: mkcert -install
  3. Generate the certificate for localhost: Navigate to the directory where you want to store the certificate files and run:
    4. Code: mkcert localhost 127.0.0.1 ::1 or mkcert "*.example.it" Generate "_wildcard.example.it.pem" and "_wildcard.example.it-key.pem".
    This command generates a trusted self-signed certificate for localhost, 127.0.0.1, and ::1 (IPv6 loopback address) in the current directory. You will find files like localhost+2.pem (the certificate) and localhost+2-key.pem (the private key).
  4. Configure your application: Use the generated localhost+2.pem as your certificate and localhost+2-key.pem as your private key in your local server or application configuration. The specific method for adding these files varies depending on the server or application you are using.
After these steps, your local application running on localhost will be served with a trusted self-signed SSL certificate, allowing you to access it via HTTPS without browser warnings.

Configuring PostgreSQL and defining users and databases

After initially installing PostgreSQL and configuring it for SSL, a primary mapper user must be created as a superuser. This can be done in psql while logged on as user postgres (the superuser defined during installation.) The following reccomendations are suggested for the use of PostgreQSL:

  1. There should be a role created with the name of mapper. This role will be the owner of all the mapper databases.
  2. There should be at least one user logon created to access PostgreSQL. This user should have superuser privileges. All user logons that will access Mapper databases should be a member of role: mapper.
  3. There will be needed a database for each city that Mapper uses. It is suggested that the names used be: stlouis, cincinnati, louisville, indianapolis and berlin. These will be the names used in the script described below.

Script to create user logon, databases and function

Once the primary user has been created as superuser, a script can be run to create the databases as well as a user defined function used by SQL queries. This script can be found in the ../Resources/sql/PostgreSQL folder named PostgreSQL_create_distance_function.sql. Several values in the script that refer to login parameters must be changed to your actual login credentials needed to login to psql. Use the following parameters for psql:
  • psql -h localhost -U your-user-id -d postgres

Once logged on in psql paste the script that has been modified with your logon credentials. (Alternatively, a -f parameter an the path to the script can also be used.)

Checking configuration

To verify that the user defined function has been installed correctly, start Mapper and select the "Sql query dialog" from the Tools menu. Select a target connection to the PostgreSQL database and run the sql command: Select distance(1,2,3,4). The desired result should be: 314.40295102362484.
